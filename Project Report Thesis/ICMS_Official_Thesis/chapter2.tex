\section{Literature Review}

\subsection{Evolution of Governance, Risk, and Compliance (GRC) Platforms}
Historical security auditing relied on point-in-time assessments, which left blind spots between evaluation periods. Organizations managed Governance, Risk, and Compliance (GRC) through manual evidence collection, and this often made the compliance state obsolete shortly after an assessment. Regulatory frameworks now require a transition toward continuous controls monitoring architectures. Standards like NIST Special Publication 800-53 Revision 5 and ISO/IEC 27001:2022 mandate ongoing monitoring to validate control implementation \cite{nist80053_2020, iso27001_2022}. The Federal Information Security Modernization Act (FISMA) and the Federal Risk and Authorization Management Program (FedRAMP) also require agencies to automate the tracking of systemic anomalies \cite{fisma_2014}. SIEM-driven compliance offers several operational advantages. Centralized log management supports audit accountability by preserving data confidentiality, integrity, and availability \cite{nist80092_2006}. Automated analysis establishes operational baselines, which helps forensic investigations during security incidents. Security administrators configure SIEM agents to track software inventories, hardware configurations, and system health. This data feeds into the GRC database to replace reactive audits with a data-driven security posture. By evaluating log streams against baselines, organizations turn evidence generation into a part of daily security operations.

\subsection{Security Information and Event Management (SIEM) Integrations}
The integration of Security Information and Event Management (SIEM) systems changes the GRC methodology. SIEM platforms are telemetry ingestion engines that replace manual log retrieval with automated data correlation. NIST SP 800-53 defines control families, such as Audit and Accountability (AU) and System and Information Integrity (SI), that require automated tracking to satisfy continuous validation requirements \cite{nist80053_2020}. Automating these controls involves mapping endpoint telemetry to regulatory requirements. Platforms like Wazuh, an open-source SIEM and Extended Detection and Response (XDR) solution, facilitate this by providing aggregation logic that maps compliance events against NIST and ISO matrices \cite{wazuh_doc}. Automated compliance mapping fills the gap between technical events and business risk. When a user modifies a protected configuration file, File Integrity Monitoring (FIM) sensors generate an event log. The SIEM correlates this event against framework matrices and flags the action as a violation of ISO 27001 Annex A.8.9 (Configuration Management) or NIST SP 800-53 control CM-6 \cite{nist800128_2011}. Analysts monitor deviations through dashboards that aggregate alert volumes and isolate non-compliant agents for remediation. The Wazuh Security Configuration Assessment (SCA) module provides the validation needed for these governance frameworks by evaluating configuration states against security benchmarks.

\subsection{Performance Bottlenecks in Telemetry Aggregation}
Calculating compliance metrics across distributed fleets exposes data aggregation limits in traditional GRC platforms. Standard relational database implementations often suffer from the N+1 query problem, where the application executes sequential retrieval loops for individual security controls. This architectural flaw imposes a linear $O(N)$ algorithmic complexity on data retrieval, which causes performance to drop as the number of monitored agents increases \cite{planetscale_n1}. High latency prevents continuous monitoring because dashboard rendering times exceed thresholds for operational visibility. The overhead of Object-Relational Mapping (ORM) frameworks extends beyond query volume. Application-level data processing, where the system retrieves full object graphs before filtering or aggregating in memory, creates bandwidth bottlenecks. This pattern forces the application server to create transient objects, which triggers garbage collection cycles that can block compliance logic. In environments where SIEM agents transmit telemetry continuously, these $O(N)$ operations lead to a loss of operational visibility.

Relational data access requires moving from sequential $O(N)$ loops to $O(1)$ set-based aggregations. Set-based modeling formalizes relational dynamics and shows that task-informed database representations retain signals more efficiently than application-level iteration \cite{kuraj_microservices_2024}. Developers optimize ORM queries by using eager loading to translate application logic into SQL JOIN clauses. Fetching related entities in a single query allows the database engine to use B-Tree indices efficiently, which reduces execution time and minimizes context switching between the application runtime and the database server. Set-based database aggregations move the workload to the relational engine. Using query projection, the system instructs the database to compute sums, averages, and conditional compliance counts internally. This reduces data transfer across the network from megabytes of row data to simple integer values. By using conditional aggregation functions, the platform achieves a consistent $O(1)$ response time. These optimizations ensure dashboard rendering remains responsive as the organizational asset inventory grows. The decision to prioritize database-side computation over application-side iteration ensures the GRC platform can process telemetry logs without exhausting computational resources.

\subsection{Modern Access Control Paradigms}
Securing the compliance data layer requires Identity and Access Management (IAM) protocols. Role-Based Access Control (RBAC) provides the foundation for authorization in distributed systems. RBAC methodologies control access to system resources based on roles assigned to a user instead of assigning permissions directly to a user identity \cite{nelson_stateless_2024}. Authentication in distributed microservices often relies on stateless session security, usually implemented via JSON Web Tokens (JWT). The authorization server signs the JWT using asymmetric encryption to prevent tampering and allow local verification without a database lookup. Authorization in the ICMS platform uses an enforcement layer that applies Zero Trust principles to the API routing logic. The system evaluates the identity context of every inbound request. Custom permission classes intercept traffic at the view layer and verify that the requester has the RBAC attributes required for the target resource. This enforcement is decoupled from the business logic, which ensures a consistent security boundary.

The security lifecycle of stateless JSON Web Tokens (JWT) includes rotation policies to mitigate risks from long-lived credentials. Traditional session IDs require database lookups for verification; JWTs carry signed claims that allow microservices to authenticate users locally. To prevent session hijacking, the platform uses a refresh token rotation scheme. When the client requests a new credential, the server invalidates the previous refresh token and issues a new pair. The architecture also uses Time-Based One-Time Passwords (TOTP) as a secondary authentication factor. TOTP algorithms rely on a cryptographic secret shared between the server and the client's authenticator app. Both entities use the current Unix timestamp as a factor in a Keyed-Hash Message Authentication Code (HMAC-SHA1) function \cite{rfc6238}. Because the 6-digit numeric code changes every 30 seconds, intercepted credentials have limited use. Secondary authentication factors provide an additional defensive layer against replay attacks. Client-side interceptors monitor for specific HTTP response states; when the server returns a forbidden status due to a missing or invalid TOTP challenge, the application redirects the user to an authentication view. This lifecycle ensures compliance data remains inaccessible to compromised endpoints.

\subsection{Containerization and Defense-in-Depth Topology}
Enterprise architecture is moving from monolithic software design toward microservices and containerized deployments. Monolithic systems couple application logic, user interfaces, and database drivers into a single deployment artifact, where a failure in one component can affect the entire environment. Containerization technologies, specifically Docker, provide a standardized runtime environment for these distributed microservices. This ensures scalability and bounded contexts through Linux kernel features. Deploying the ICMS components via isolated Docker virtual bridge networks establishes a defense-in-depth topology. The architecture separates the public-facing API gateway layers from the private persistent storage layers, such as PostgreSQL and Redis. By binding these data tiers to internal Docker bridge networks, the system remains inaccessible to external scans. This isolation prevents actors from establishing direct TCP connections with the database and forces interactions through the authenticated business-logic layer. Adherence to hardening standards, such as NIST SP 800-190 and the CIS Docker Benchmark, further reduces execution environment vulnerabilities \cite{nist800190_2017, cis_docker_2020}.

\subsection{Cognitive Load and HCI in Security Dashboards}
Security Operations Centers process large volumes of diagnostic data, which can trigger alert fatigue. Legacy GRC platforms present analysts with unfiltered data in dense tables, leading to sensory overload and diagnostic errors. High cognitive load correlates with delayed incident response and operator burnout \cite{mit_hci_security_2022}. Reducing cognitive strain requires the application of User Interface (UI) design principles based on human-computer interaction studies. Modern rendering engines use CSS Flexbox and Grid modules, which allow components to wrap and scale based on viewport dimensions \cite{mdn_flexbox}. The ICMS platform uses modular card components and color scaling, such as red for critical exploits and grayscale for benign logs, to guide the analyst's focus. Using depth distinctions separates interactive components from background data, which structures telemetry into a decision-support tool.

\section{Analysis of Existing Systems}

\subsection{Manual Spreadsheet Auditing}
Traditional governance relies on labor-intensive processes including spreadsheets, task-tracking tickets, and point-in-time audits. This fragmented approach fails to scale in modern IT environments because the compliance state captured during an audit becomes obsolete once the assessment ends. The reliance on manual sampling and evidence collection creates blind spots where vulnerabilities remain undetected between audit cycles. The structural limits of spreadsheet applications lead to performance issues and data corruption when tracking many configuration parameters. Manual mapping also increases the probability of human error as analysts interpret technical data against regulatory constraints.

\subsection{Vanta (Commercial SaaS)}
Vanta operates in the commercial Software-as-a-Service (SaaS) continuous monitoring sector. The platform speeds up evidence collection by deploying proprietary agents and using API connectors to integrate with cloud providers and identity systems. This commercial solution introduces risks regarding data sovereignty and vendor lock-in. As a multi-tenant cloud environment, Vanta requires organizations to transmit security telemetry to its external infrastructure. This data transmission increases the attack surface. Vanta is a proprietary system, so its closed-source algorithms prevent organizations from independently verifying how telemetry events map to compliance controls. This lack of transparency forces organizations to rely on the provider's internal security assertions.

\subsection{Drata (Commercial SaaS)}
Drata provides automated compliance tracking through a multi-tenant SaaS architecture. While the platform offers integrations and pre-mapped framework tracking, it involves risks regarding external data storage. Organizations using Drata export their infrastructure metadata to the provider's cloud, which can violate data sovereignty requirements in the defense and financial sectors. The closed-source nature of Drata restricts security engineers from inspecting the underlying evaluation logic. This prevents custom modifications to the compliance engine, meaning that organizations with unique architectures cannot extend the system without relying on the vendor. This ensures the platform remains a closed-box system rather than a verifiable tool.

\subsection{AuditBoard (Enterprise GRC)}
AuditBoard targets the enterprise GRC market and focuses on risk management, ESG reporting, and internal audit synchronization. Despite its features, AuditBoard can be rigid to integrate. The platform has high licensing costs and requires professional service engagements for deployment, resulting in long setup cycles. This enterprise architecture compares poorly against containerized solutions that deploy quickly. AuditBoard relies on proprietary connectors to interface with security tools, which establishes a closed-box mapping approach. Security engineers cannot manipulate the logic linking SIEM alerts to organizational risk matrices. This opacity limits the platform's utility in environments that require verifiable compliance states.

\section{Summary of Advantages}
The ICMS platform provides operational and technical advantages that address the flaws of legacy auditing and commercial SaaS offerings:

\begin{itemize}
    \item \textbf{Data Sovereignty via Docker Bridge Isolation:} The platform confines all PostgreSQL database interactions to a private virtual network, which ensures compliance telemetry remains isolated from the public internet and external third-party vendors.
    \item \textbf{Transparent, Verifiable Mapping:} By using an open-source Django backend, organizations can programmatically inspect and verify the logic linking raw Wazuh SIEM alerts to governance controls.
    \item \textbf{Deterministic $O(1)$ Database Performance:} Set-based aggregations replace standard ORM loops, allowing the system to render compliance dashboards with low latency regardless of the agent inventory size.
    \item \textbf{Zero-Cost Licensing Architecture:} The operational stack relies on open-source technologies like Wazuh, PostgreSQL, and Python, which removes the financial burden of commercial SaaS fees.
    \item \textbf{Automated Telemetry Deduplication:} The implementation of a Worst-Case Priority algorithm ensures that conflicting telemetry reports from different sensors are resolved consistently, which prevents false-positive compliance states.
\end{itemize}
