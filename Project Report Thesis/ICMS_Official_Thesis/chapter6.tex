\chapter{System Testing and Evaluation}
The testing and evaluation phase verified that the Intelligent Security Compliance Management System (ISCMS) meets the functional requirements and architectural specifications from the design phase. Testing confirmed that the platform provides accurate telemetry ingestion, stable security governance, and a consistent user experience. Assessment methods included Graphical User Interface (GUI) validation, usability assessments, performance benchmarking, exception handling verification, and security testing. These tests identified edge cases and validated the deterministic compliance mapping engine.

\section{Critical Appraisal and Limitations}
The ISCMS platform maps heterogeneous Security Configuration Assessment (SCA) data to structured GRC controls. The asynchronous processing tier, using Celery and Redis, decouples SIEM polling from the user interface to keep it responsive during data ingestion. However, an honest engineering appraisal reveals limitations. Periodic polling of the Wazuh REST API introduces latency between endpoint configuration changes and their reflection on the dashboard. This works for periodic auditing but does not match the near-real-time synchronization possible with socket-based streaming. Multi-page PDF audit reports are also CPU-intensive; while background workers handle them, they still increase load on the containerized environment during reporting periods.

\section{Testing Environment and Methodology}
The Quality Assurance (QA) process covered the full stack of the ISCMS platform. Muhammad Hammad Chaghtai validated the frontend and integration layers, testing the GUI and usability of the React SPA. This included verifying route guarding, state persistence in the AuthContext, theme toggling, and the performance of Recharts-based visualizations. Because the Wazuh SIEM manager was hosted on localized hardware, Muhammad Ali Bukhari validated the backend telemetry modules. This covered testing the Python client's authentication with the SIEM node, verifying network exception handling, and confirming the integrity of API synchronization tasks. Testing ran in a distributed containerized environment that simulated standard home-lab conditions.

The following fourteen test cases constitute the QA suite used to validate the ISCMS platform across IAM, frontend UI, backend API, SIEM telemetry, and reporting layers. Positive and negative scenarios are documented to demonstrate system correctness and exception handling. Each subsection below maps directly to a parent Use Case (UC-01 through UC-06).

\subsection{Security and Penetration Testing}
The platform implements a defense-in-depth strategy against unauthorized access and data manipulation. TOTP-based 2FA adds a cryptographically secure second authentication factor, protecting administrative access even if primary credentials are compromised.
