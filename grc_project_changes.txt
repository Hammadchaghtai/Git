========================================================
GRC PLATFORM - COMPREHENSIVE CHANGES LOG & CONTEXT
========================================================

This document outlines all tracking and modifications done to the GRC platform ecosystem over the recent development cycles. It encapsulates the full context of what has natively been achieved locally before matching against the upstream GitHub repository.

---
1. UI/UX & THEME MODERNIZATION
---
- "True OLED Dark Mode" Overhauls: 
  Fixed the background rendering bug on `DashboardLayout.jsx` where the `<main>` tag overrode dark elements with hardcoded grey. Enforced deep `#000000` pitch-black backgrounds universally using tailwind dynamic mapping (`dark:bg-black text-[#0f172a] dark:text-white`).
- Native Dark CSS Injection:
  Altered `index.css` to globally map variables over the primary dashboard body when the `.dark` class triggers.

---
2. MANAGE ADMINISTRATORS MODULE (`ManageAdmins.jsx`)
---
- Auditor Expiry UI Upgrade:
  Swapped out standard "hours" integers for the native `<input type="datetime-local" />` input logic on the Invite modal. This prevents math tracking errors and accurately sets expiration at precise times using exact timestamps globally offset correctly.
- Enhanced "View Details Panel" (Slide-Out Slider):
  Instead of simple modals, we attached an expansive right-slide tray that gives a comprehensive overview of the target identity (displaying avatar images natively, password altered statuses, and exact countdown ticking clocks for Auditor expiry limits).
- Verification Credentials Interstitial (`RegenerateModal`):
  Previously, resetting credentials automatically nuked the old ones. We added a safety dialog interceptor before regenerating credentials. It pre-populates their email and asks "Do you want to send the new TOTP payload to a different email address?" allowing administrators to recover locked users securely.
- Mandatory Change Password "Reminders":
  Added visual "Bell" indicators highlighting administrators who have NEVER changed their initialized passwords. Pressing this bell now properly queues and fires genuine backend API instructions (`/api/users/{id}/send-reminder/`).

---
3. IDENTITY SETTINGS REDESIGN (`Settings.jsx`)
---
- Profile & Security Tab Integration:
  Wired robust update engines into `Settings.jsx` separated into cohesive logical structures (My Identity & Security vs Global System Configurations).
- Secure Password Toggles (Eye Icons):
  Added absolute `<button>` overlays switching password input field bindings dynamically from `"password"` -> `"text"` (using Lucyde 👁️ & 👁️‍🗨️ graphics). This resolves issues where administrators incorrectly mismatch confirming the newly constructed passwords, causing silent save rejections.
- Multipart File Support (Avatars):
  Introduced pure native filesystem injections (`FormData`) to bridge display names, timezones, and profile pictures physically to the server mapping. 

---
4. BACKEND INTEGRATION PIPELINES (`views.py` & `urls.py`)
---
- Dashboard Mini-Audit Filter Fix:
  In `DashboardSummaryView`, the Timeline previously mixed up Authentication logins, Layouts, and Profile updates into the dashboard view. This has been forcefully bound via Django `.filter(module__icontains="Policy")`. Now, ONLY authentic system Policy alterations get painted.
- Verified Dedicated SMTP Hook `_send_reminder_email()`:
  A completely new background HTML threading protocol was written to parse `send_reminder`. The system actively shoots formal, formatted security warnings dynamically mapping URL entry points back to the React localhost explicitly telling users to navigate to their 'Settings > My Identity & Security' menu globally.
- Media Directories (`MEDIA_ROOT` & URL Routing):
  Configured `settings.py` adding `MEDIA_ROOT` and `STATIC_ROOT`, while altering `core/urls.py` static router deployment to allow React Axios requests to correctly read back `.png` and `.jpg` uploads via URL object parameters without suffering static 404 blockages.

========================================================
CONCLUSION
========================================================
The local environment is fully committed under the local Git history. It bridges advanced functional React frontends mapping seamlessly to secure DRF (Django REST Framework) environments without trailing memory bugs, misaligned themes, or un-routed actions.
